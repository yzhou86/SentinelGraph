01 / BACKGROUND背景与项目目标

安全团队需要同时分析网络连接、身份登录、终端进程、云审计和漏洞发现。它们的共同难点不是“缺少一条日志”，而是在大规模、持续写入的数据中，将跨域证据关联成一个可以审计的故事。

传统图数据库的压力

在百亿级实时关系流下，全图扫描、中心节点热点和高并发写入容易成为瓶颈。

本项目的选择

把事实日志、边表、检测和向量都放入 StarRocks；图查询从一个入口实体做有界邻域展开。

面向 Agent，而非替代研判

Agent 获得事件、边、告警和处置上下文；模型不能替代事实源、检测规则或人工确认。

开源参考实现

适合 POC、客户演示和平台原型。生产部署仍需补足租户隔离、RBAC、审计、压测和治理。

02 / ARCHITECTURE从日志到可解释结论

核心设计把“事件事实”和“推理层”分开：事实保持在 OCSF 原始事件及图边中，向量检索和 LLM 只补充上下文与表达。

INPUT多源日志

流量、主机、云审计、漏洞、报告与 Playbook。

NORMALIZEOCSF 规范化

保留原始 JSON，同时投影高频字段。

LAKEHOUSEStarRocks

事件热表、实体观测、边表、告警、文档向量。

CONTEXT关联与检索

有界图遍历、规则检测、向量召回、文本补图。

REASONAgent 调查

仅基于证据生成假设、影响和处置建议。

关键原则：先查事实，再做推理。任何攻击结论都应能回溯至 event_uid、alert_id 或带来源的文本证据。

03 / FUNDAMENTALSOCSF 是什么？

OCSF（Open Cybersecurity Schema Framework）是一个供应商和存储无关的安全数据标准。它不绑定某个 SIEM、数据湖或图数据库，而是为事件类别、身份、端点、资产、云账户和扩展字段提供共同语义。

项目如何使用 OCSF

OCSF 信息StarRocks 投影图中的实体
metadata.uid、time、事件类别event_uid、event_time、class/category/type UIDevent:{uid}
actor.user用户 UID、用户名user:{uid}
src_endpoint / dst_endpoint源/目的 IP、端口、协议ip:{address}
device、resource、cloud.account资产、资源与云账户列asset:*、resource:*、cloud_account:*
未投影字段与供应商扩展raw_event JSON按需扩展 normalizer

因此，接入者可以从原生 OCSF 开始，也可以先用内置适配器把 ECS、CloudTrail、Zeek 或通用 JSON 映射成 OCSF。原文仍被保存，避免在统一 schema 时丢失调查所需细节。

04 / OLAP + LAKEHOUSE为什么是 StarRocks？

项目不是把全部关系搬进独立图数据库，而是使用 StarRocks 的列式 OLAP 能力承载高并发事件事实、聚合检测、边表查询和文档向量。这样能在同一引擎中处理实时热数据和湖仓冷数据，并减少跨系统同步。

事件热表

按事件日期分区，面向时间窗口聚合、规则检测和高频属性过滤。

追加式实体观测

不维护高竞争的全局节点，而是记录实体出现时间，查询时再聚合。

事件中心边表

每条 OCSF 事件连到用户、IP、资产、资源或云账户，天然保留时间与租户范围。

Lakehouse 扩展

提供 Kafka Routine Load 与 Iceberg/Parquet 模板，用于流批一体与冷数据联查。

05 / GRAPH + DETECTION图关联、规则和告警

图不是全局递归扫描。调查从一个实体（如 user:alice 或 asset:web-01）出发，以 1–3 跳和每跳数量上限读取邻域。这样能表达“账号 → 登录事件 → 主机 → 外联 IP → 漏洞”的路径，同时控制大规模边表的查询成本。

检测规则

YAML 规则定义时间窗口、分组键、阈值及受控谓词，编译为有租户、时间下界和 LIMIT 的聚合 SQL。告警包含关联键及其证据事件，而不是只有一段不可复核的摘要。

重要区分：相关性不等于归因

时间上接近、同一用户或同句文本共现，能够提高调查优先级；但是否为攻击、是否已经外传数据、是否归属于某个组织，都需要更多证据和人工流程确认。

06 / RETROSPECTIVE历史行为聚类与事后复盘

实时检测回答“现在发生了什么”；事后分析回答“在这段历史里，哪些跨域行为值得重新调查”。POST /v1/retrospective/analyses 先由 StarRocks 按租户、日期分区和精确时间窗裁剪 OCSF 事件，再只在受 max_events 限制的结果中进行聚类。

会话化，而非全局扫图

只有在配置的时间间隔内共享用户、IP、资产、资源、云账户或 trace 的事件才会连成候选簇。

可解释的基线

开始时间前的 class_uid 计数只用于标记未见或低频事件类别，避免不可解释的黑盒异常分。

证据优先级

每个簇给出风险排序、共有实体、信号、推荐核验项和可回溯的 event_uid。

边界明确

共享 IP、资产或时间邻近是调查线索，不等于攻击成立、数据外传或攻击者归因。

默认分析最近 7 天并以此前 30 天为基线；范围、会话间隔、事件上限和簇数量都可在 API 中显式控制。长时间范围应按日期分区离线批处理，而不是放大在线读取上限。Mock 也能直接展示同一返回契约，但不会查询数据库或 LLM。

07 / VECTOR + GRAPHRAG向量检索与 GraphRAG 的位置

安全 Playbook、处置记录和威胁情报文本可形成文档向量，借助 StarRocks HNSW 索引进行相似检索。GraphRAG 的关键不是“让模型拥有图”，而是将受限图邻域、事件证据、告警和相关文档拼成上下文，让模型在边界内辅助研判。

  • 向量相似度用于找相关文本，不是入侵证明。
  • LLM 输出必须说明不确定性，并引用事件或告警 ID。
  • 向量索引是可选能力；没有它，事件、图关联与检测仍可独立运行。

07 / TEXT-TO-GRAPH从安全文本补充图谱

事件日志不是唯一证据。安全报告、工单、威胁情报和分析备注也常包含关键 IOC。本项目的 Text-to-Graph 能力先用离线规则识别 IPCVE域名URL邮箱SHA-256，并生成可追溯的关系。

  • document → mentions → IOC：直接指标关系，可重复解析。
  • co_mentioned_in_sentence：同句上下文，仅作调查入口，低置信度。
  • 可选 LLM 只能在已识别实体之间提出白名单关系；无原文证据、未知实体或不允许关系会被拒绝。
  • 全部文本关系以 pending_review 开始，并保留来源、证据、置信度和追加式审核记录。

08 / DEMO MODESMock 与 Live：如何演示与落地

Mock 模式：零依赖演示

不需要 StarRocks、LLM 或网络。可切换凭证攻击、云账号接管、终端横向移动/勒索三类场景，所有按钮返回一致的事件、告警、图、文本关系与处置建议。

Live 模式：真实环境调查

使用配置的 StarRocks、可选向量索引与 LLM。用户可配置第三方 StarRocks 连接，导入真实事件或安全报告；数据与模型密钥由服务端管理。

建议客户演示顺序：选择场景 → 载入攻击故事 → 查看告警和有界图 → 调用 Agent 调查 → 解析报告为图关系 → 切换到 Live 说明同一接口如何进入真实环境。

09 / INTEGRATION第三方 REST API

所有第三方接口以 /v1 为前缀。可访问 第三方集成文档查看完整 curl 示例、能力发现、调用约定与认证说明；也可以在 Swagger 中查看请求/响应模型，或读取 OpenAPI JSON 生成客户端。

# 配置可选集成密钥后，/v1 请求携带 X-API-Key curl http://localhost:8000/v1/integration/capabilities \\ -H 'X-API-Key: <operator-issued-key>' # 常见入口：/v1/events、/v1/ingest/{format}、/v1/alerts、 # /v1/graph/{entity_id}、/v1/agent/investigations、/v1/text-graph/extract

当 INTEGRATION_API_KEYS 未配置时，API 保持本地开发兼容。生产系统必须通过 HTTPS 与网关部署，并结合 OIDC、细粒度租户授权、限流和审计。

10 / PRODUCTION生产安全边界与下一步

  • 在入口层实施 OIDC/mTLS、租户身份映射、速率限制和审计；示例 API 不替代企业身份体系。
  • 使用 Secret 注入 StarRocks 与 LLM 凭据；不要把密钥、原始敏感日志或客户数据放入浏览器存储。
  • 为 StarRocks 配置最小权限、TLS、正确副本数、分区策略和真实负载压测。
  • 对 PII、原始日志与模型上下文实施分类、掩码、保留策略和访问审计。
  • 将 LLM 与文本抽取输出视为待验证建议；闭环到人工审核、SOAR 或既有响应流程。
从 POC 进入生产的建议顺序：先标准化数据与租户治理，再验证规则、图查询和容量；随后评测 embedding/LLM；最后接入审批、审计和自动化处置。
本页与项目 README 保持同一架构与安全边界：OCSF 为事实语义，StarRocks 为分析与关联底座，图与 Agent 输出必须可回溯到证据。
