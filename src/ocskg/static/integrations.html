VERSIONED REST API · OCSF · STARROCKS

让第三方系统
可靠地接入安全图谱。

使用稳定的 /v1 REST 接口接入 OCSF 日志、读取有界攻击图、执行检测、触发证据化 Agent 调查，并将安全报告补充为可审核的文本关系。

安全边界设置 INTEGRATION_API_KEYS 后，全部 /v1 接口要求 X-API-Key。密钥为空时仅适合本地开发；生产环境还应使用 HTTPS、API Gateway、限流、租户鉴权与审计。
01 / INGEST规范化与写入

直接提交 OCSF，或通过 ECS、CloudTrail、Zeek、JSON 适配器映射后写入 StarRocks。

02 / CORRELATE受限图与检测

读取按租户和跳数限制的邻域，运行规则并获取带证据 ID 的告警。

03 / REASON证据化调用

向 Agent 调查或文本图谱接口提交问题与报告；模型建议始终保留审核状态。

开始调用

1. 发现能力

GET/v1/integration/capabilities

返回 API 版本、认证是否启用、可用适配器和功能开关。推荐集成器在启动时读取。

2. 认证

当运营方配置了密钥，在每个 /v1 请求附加：

X-API-Key: <operator-issued-key>

密钥不通过查询参数传递，也不会由服务端返回。

curl http://localhost:8000/v1/integration/capabilities \\
  -H 'X-API-Key: <your-key>'

核心接口

POST/v1/events

批量写入原始 OCSF JSON。服务端同时投影列、实体观测和事件中心边。

适用于网关、采集器和流式微批。

POST/v1/ingest/{format}

接收 ecs、cloudtrail、zeek、common_json 或 auto。

适用于已有 SIEM、云审计和 NDR 数据。

GET/v1/graph/{entity_id}

按租户、入口实体和 1–3 跳深度查询攻击邻域；不会执行无界全图扫描。

POST/v1/agent/investigations

获取图边、相关 OCSF 原始证据与向量检索上下文；可选调用已配置 LLM。

POST/v1/text-graph/extract

从安全报告提取 IOC 与可审核关系。规则模式离线可用；LLM 模式只允许提出受限关系。

GET/v1/alerts

查询规则及关联告警。每个告警包含规则、严重度、关联键和证据事件 ID。

历史复盘与行为聚类

POST/v1/retrospective/analyses

读取指定租户的有界 OCSF 历史时间窗，按同一会话间隔内的共享用户、IP、资产、资源、云账户或 trace 构造行为候选簇。响应包含事件证据、共有实体、class 基线对比和可解释排序；不返回攻击归因。

curl -X POST http://localhost:8000/v1/retrospective/analyses \\
  -H 'content-type: application/json' \\
  -H 'X-API-Key: <your-key>' \\
  -d '{"tenant_id":"acme","lookback_hours":168,"baseline_hours":720,"session_gap_minutes":30,"max_events":20000,"cluster_limit":12}'

Live 查询同时使用 tenant_id、event_date 与 event_time；单次最多读取 50,000 条事件。Mock 模式返回固定历史证据，不访问 StarRocks 或 LLM。

示例：接入、调查与文本补图

# 1. 摄入 OCSF 事件
curl -X POST http://localhost:8000/v1/events \\
  -H 'content-type: application/json' \\
  -H 'X-API-Key: <your-key>' \\
  -d '{"tenant_id":"acme","events":[{...OCSF event...}]}'

# 2. 读取受限攻击图
curl 'http://localhost:8000/v1/graph/user:alice?tenant_id=acme&depth=2' \\
  -H 'X-API-Key: <your-key>'

# 3. 把事件报告补充进图谱（默认待人工审核）
curl -X POST http://localhost:8000/v1/text-graph/extract \\
  -H 'content-type: application/json' \\
  -H 'X-API-Key: <your-key>' \\
  -d '{"tenant_id":"acme","source_id":"case-0810","content":"web-01.prod.demo connected to 198.51.100.9 after CVE-2025-9999.","extractor":"rules","persist":true}'

调用约定

租户与幂等

  • 所有业务调用都传入 tenant_id。
  • 使用上游事件的稳定 UID，避免重复重放时产生新的事实。
  • 对失败请求使用指数退避；不要无界重试写入。

证据与审核

  • Agent 输出必须引用 event_uid 或 alert_id。
  • 向量相似度与句内共现都不是入侵证明。
  • 文本关系以 pending_review 开始，审核决定为追加审计记录。
完整字段定义、请求模型和响应模型请使用 交互式 OpenAPI 文档；机器客户端可直接读取 OpenAPI JSON。
